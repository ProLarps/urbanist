# docs/API.md — Спецификация серверного API «Дом напротив» — v2

Формат данных — JSON в UTF-8. Документ самодостаточный: реализация на любом языке по этому тексту должна дать совместимый с клиентом протокол.

## 0. Что изменилось против черновика v1 (для фронтенда)

| Было (v1) | Стало (v2) |
|---|---|
| Общий город: общий бюджет, метрики `qol/trust/heritage/culture` | **Личный бюджет (`money`) и рейтинг (`rating`) у каждого игрока**. Общих метрик нет. |
| Слушание: `act` открывает голосование жителей и ИИ-агентов, отказ возможен | Слушаний нет. `act` **сразу** стартует проект, если у игрока есть на это бюджет. Голоса заменены диалогом с местными жителями чанка (см. §8). |
| `voteCast` / `vote` | Удалены. Воля жителей измеряется по ходу чата и применяется после реновации. |
| `budget` / `judge` (обучающая проверка сметы) | Удалены. |
| Статусы здания `idle → planned → renovating → done` | `idle → renovating → done` (промежуточный `planned` упразднён). |
| Чат только с агентами по `agentId` | Чат **локальный для чанка**: ареной выступает чанк игрока. Прямые диалоги — по `agentId`, ambient-сообщения NPC (городские «прожекторы» как в Cities: Skylines) pressured в тот же канал. |

| `ping {t}` / `pong {t}` | Payload key `t` конфликтовал с типом кадра — переименован: `ping {n}` / `pong {n}`. |

| Схема БД: без комнат/выдач | + таблицы `rooms`, `grants`; `votes` удалена. Score per-room, лучший score хранится в `players.best_score`. |

## 1. Назначение

Сервер держит полный мир игры и является единственным источником истины. Клиент (браузер, three.js) получает только часть мира — те 9 чанков (3×3), которые окружают его. Клиент никогда не хранит больше 9% данных о мире.

Сервер также владеет игровым состоянием, базой данных и ИИ-агентами. Клиент не содержит логики экономики, симуляции и не хранит состояние агентов.

## 2. Способы связи

- **HTTP** — для получения токена, проверки живости сервера, раздачи клиентских файлов и **CRUD комнат/профилей**.
- **WebSocket** — всё интерактивное взаимодействие: перемещение, докачка чанков, действия по зданиям, диалоги с жителями, ход раунда.

Все сообщения — одиночные JSON-объекты в одном текстовом кадре WebSocket. Каждый объект содержит строковое поле `t` — тип сообщения. Порядок полей не важен.

### 2.1 HTTP: `POST /api/auth`

Обмен имени игрока на токен для подключения к WebSocket. Токен кладётся клиентом в `localStorage` и переиспользуется при перезагрузке страницы.

Тело запроса:

```json
{ "name": "Аня", "avatar": 3, "room": "default" }
```

- `name` — строка, после обрезки пробелов 1..24 символа. Пустое или слишком длинное имя → ошибка.
- `avatar` — целое 0..7, необязательное, по умолчанию 0.
- `room` — код комнаты, необязательное, по умолчанию `"default"`. Комната должна существовать (см. §2.4) — иначе ошибка `room_not_found`.

Успешный ответ 200:

```json
{
  "token": "eyJ...signature",
  "playerId": "p_8f3a1c",
  "name": "Аня",
  "color": "#4f9dff",
  "world": { "chunks": 10, "lotsPerChunk": 8, "totalLots": 6400, "viewChunks": 9 },
  "protocol": 2
}
```

Ошибка 400: `{ "error": "bad_request", "detail": "имя должно быть от 1 до 24 символов" }`. Ошибка 404: `{ "error": "room_not_found" }`.

Токен — непрозрачная строка с подписью: `base64url(payload).base64url(подпись)`, payload — `{ "pid": "...", "name": "...", "room": "...", "exp": <unix> }`, подпись — HMAC-SHA256 от payload с секретом сервера. Время жизни — 7 суток. Секрет хранится в файле, чтобы токены переживали перезапуск процесса.

### 2.2 HTTP: `GET /api/health`

```json
{ "ok": true, "uptime": 128.4, "players": 2, "chunks": 100, "buildings": 6400, "tps": 10 }
```

### 2.3 HTTP: профили, лидерборд

- `GET /api/players` — список игроков сервера (служебный): `[{ "id", "name", "color", "lastSeen" }]`.
- `GET /api/players/{id}` — **профиль** (требование регламента): `{ "id", "name", "avatar", "color", "bestScore", "createdAt", "lastSeen" }`.
- `GET /api/leaderboard` — глобальный рейтинг по лучшим сессиям: `[{ "playerId", "name", "bestScore", "room", "ts" }]`.
- `GET /api/rooms/{code}/scoreboard` — счет текущей комнаты: `[{ "playerId", "name", "money", "rating", "score" }]`, `score = money × rating`; лучший результат игрока в комнате пишется в профиль.

### 2.4 HTTP: CRUD комнат (требование регламента)

Комната — независимый город (свой мир, свои чанки, свои раунды). Все операции требуют токен (`Authorization: Bearer`).

| Метод | Путь | Тело | Ответ | Права |
|---|---|---|---|---|
| `POST` | `/api/rooms` | `{ "name"?: "…" }` | `201 { "code": "K7Q2MX", "name": "…", "ownerId": "p_…" }` | любой авторизованный |
| `GET` | `/api/rooms` | — | `[{ "code", "name", "players", "maxPlayers", "createdAt" }]` | любой авторизованный |
| `GET` | `/api/rooms/{code}` | — | `{ "code", "name", "ownerId", "maxPlayers", "players": [{ "id", "name", "color", "avatar" }] }` | любой авторизованный |
| `PATCH` | `/api/rooms/{code}` | `{ "name"?, "maxPlayers"? }` | `200 { ok: true }` | владелец комнаты |
| `DELETE` | `/api/rooms/{code}` | — | `200 { ok: true }`; активное WS-соединение игроков закрывается кодом **4404** | владелец комнаты |

Код комнаты — 6 символов (A-Z0-9 без похожих). `maxPlayers` по умолчанию 8.

### 2.5 HTTP: статика

- `GET /` — HTML-страница клиента.
- `GET /assets/...` — сборка клиента.
- `GET /shared/protocol.js` — общий файл констант протокола (единый источник истины для обеих сторон).

## 3. WebSocket: подключение и жизненный цикл

Подключение: `ws://<адрес>:8080/ws?token=<token>`.

Сервер проверяет подпись и срок действия токена **до** установления соединения.

| Код | Значение |
|---|---|
| 4400 | токен не передан |
| 4401 | токен неверный или истёк |
| 4001 | попытка игрового сообщения до авторизации |
| 4404 | комната удалена (CRUD DELETE) |

Ожидаемая последовательность: подключение с токеном → `authOk` → сервер сразу выдает стартовый чанк (`grant`) → `chunkPick` → `assigned` (таймер раунда) → `needChunks` и `move` по ходу игры.

Сообщение `auth` (`{ "t": "auth", "token"?, "name", "avatar"? }`) сохранено для клиентов, подключившихся без токена: с токеном — привязка профиля, без — создание нового.

## 4. Мир

| Параметр | Значение |
|---|---|
| Чанков по оси | 10, итого 100 чанков |
| Участков в чанке | 8 × 8 = 64 |
| Всего участков | 6400 |
| Радиус загрузки | 1 → 3 × 3 = 9 чанков (9% от мира) |
| Размер участка | 4 мировые единицы |
| Размер чанка | 32 мировые единицы |

`lotId` — линейное число 0..6399:

```
cx = floor(lotId / 64 / 10)      — индекс чанка по X
cz = floor((lotId % 64) / 8)      — индекс чанка по Z
ix = floor(lotId / 64) % 10 — индекс участка по X внутри чанка
iz = (lotId % 64) % 8             — индекс участка по Z внутри чанка
```

Состояние здания:

| Поле | Тип | Смысл |
|---|---|---|
| `id` | int | lotId |
| `type` | int | 0 пустырь, 1 панелька, 2 кирпичный дом, 3 хрущёвка, 4 особняк, 5 завод, 6 сквер, 7 магазин |
| `floors` | int | этажи |
| `condition` | float 0..1 | износ (0 — новое, 1 — руина) |
| `heritage` | float 0..1 | культурная ценность |
| `residents` | int | жильцы |
| `status` | string | `idle` → `renovating` → `done` |
| `progress` | float 0..1 | ход стройки |
| `needs` | bool | здание требует реновации (участвует в目标任务 раунда); вычисляется из `condition` |

## 5. Сообщения: клиент → сервер

| `t` | Поля | Правила и ответ |
|---|---|---|
| `auth` | `token?`, `name`, `avatar?` | Привязка/создание профиля. Ответ `authOk` или `authFail`. |
| `move` | `x`, `z`, `dir` (0..7), `anim` (`idle`/`walk`) | Смещение не более 6 единиц/сек. Анти-чит на сервере. |
| `needChunks` | `cx`, `cz` | Смена чанка камеры. Ответ `chunks` + `chunkRevoke` (`full`/`delta` — см. §7). |
| `chunkPick` | `cx`, `cz` | Выбор чанка из предоставленных кровом `grant`. Ответ `assigned` или `toast`. |
| `act` | `lotId`, `action` (`renovate`/`cancel`/`focus`), `scenario` | `renovate`: списывает стоимость, здание → `renovating`, таймер стройки. Только для зданий **назначенного** игроку чанка. `cancel`: отмена; деньги не возвращаются. `focus`: деталей здания. Ответ `toast` (или ошибка), затем `stats`. |
| `chat` | `agentId?`, `text` | 1..500 символов. С `agentId` — прямой диалог с жителем (`agentSay`…`agentEnd`); без — публичная реплика в чат текущего чанка (видят те, кто в этом чанке; жители могут отреагировать ambient-сообщением). |
| `chatEnd` | `agentId` | Завершить диалог. Ответ `agentEnd`. |
| `chatHistory` | `agentId` | История диалога. Ответ `chatHistory`. |
| `subscribe` | `channels` (массив из `journal`, `stats`, `players`) | Подписка на рассылки. |
| `ping` | `n` (число) | Ответ `pong` с тем же `n`. ВАЖНО: в черновике payload тоже назывался `t` и конфликтовал с типом кадра — переименован в `n`. |

## 6. Сообщения: сервер → клиент

| `t` | Поля |
|---|---|
| `authOk` | `playerId`, `you` (`{ id, name, color, avatar, money, rating, alive, room }`), `world`, `serverTime`, `protocol` |
| `authFail` | `reason` (`bad_token`, `bad_name`, `room_full`) |
| `grant` | `options` — массив `{cx, cz}` (N вариантов), `cycle` — номер цикла |
| `assigned` | `cx`, `cz`, `deadline` — unix время до конца раунда |
| `chunks` | `chunks` — массив ChunkDTO (полные чанки) |
| `chunkDelta` | `cx`, `cz`, `upserts` (BuildingDTO), `removed` (lotId) |
| `chunkRevoke` | `cells` — `[cx, cz]`, чанк неактуален, вычистить кеш |
| `players` | `players` — PlayerDTO в зоне загрузки |
| `playerUpdate` | `id`, `x`, `z`, `dir`, `anim` — 10 Гц |
| `playerLeave` | `id` |
| `npcUpdate` | `npcs` — NpcDTO, 4 Гц |
| `agentSay` | `agentId`, `text`, `fact?`, `memory?` — реплика/ambient сообщение |
| `agentEnd` | `agentId` — реплика/диалог завершена |
| `chatHistory` | `agentId`, `lines` — `[{role, text, ts}]` |
| `stats` | `money`, `rating`, `cycle`, `pending` (`[{cx, cz, cyclesHeld, deadline?}]`), `skipped` — рассылается при изменении |
| `toast` | `kind` (`info`/`warn`/`error`/`ok`), `text` |
| `gameOver` | `reason` (`bankrupt`, `low_rating`) — поражение;Socket не закрывается: игрок может наблюдать |
| `journal` | `entries` — `[{ts, kind, author, text, meta}]` |
| `pong` | `n` — эхо из `ping` |

Структуры:

```
BuildingDTO = { id:int, type:int, floors:int, condition:float, heritage:float,
                 residents:int, status:string, progress:float, needs:bool }
ChunkDTO    = { cx:int, cz:int, buildings:[BuildingDTO] }
PlayerDTO   = { id:string, name:string, color:string, x:float, z:float, dir:int, anim:string }
NpcDTO      = { id:string, archetype:string, name:string, country:string, x, z, tx, tz:float, color:string }
```

## 7. Правила докачки чанков

1. Сервер держит весь мир целиком. Клиент видит только 3×3 чанка вокруг чанка камеры и получает данные о **назначенных ему** чанках независимо от камеры.
2. `needChunks(cx, cz)` → сервер: отзывает выпавшие (`chunkRevoke`), присылает полные (`chunks`) для новых и дельты (`chunkDelta`) для уже полученных.
3. Клиент хранит ≤ 9 чанков камеры + свои назначенные.
4. Движения других игроков ретранслируются только в их зоны загрузки; глобально — только id, имя, цвет.

## 8. Экономика, раунды и убеждение (переработанный раздел)

**Состояние игрока**: `money` (бюджет) и `rating` (множитель-процент, старт 1.00). Итоговый score сессии: `score = money × rating`. Лучший score игрока сохраняется глобально в профиле.

**Раунд**:
1. Игрок получает `grant` с N стартовыми вариантами (первый grant — 1 случайный чанк, не занятый другим игроком; далее N=2 соседних незанятых чанка).
2. `chunkPick` → `assigned` c дедлайном — таймер раунда (по умолчанию 300 с, настраивается).
3. В течение раунда игрок реновирует **требующие** (`needs=true`) здания назначенного чанка, выбирая сценарий для каждого.
4. Чанк считается **реновированным**, когда все `needs`-здания переведены в `done`. Тогда раунд закрывается досрочно.

**Завершение раунда**:
- успех: выдаётся следующий `grant` (N соседних), счётчик `cycle++`.
- таймаут: штраф — `rating − 0.10`, `money − 20%`; чанк помечается пропущенным в `stats.pending`. Если чанк пропущен подряд **4 цикла** — он удаляется из выдачи («skipped»), однократный штраф `rating − 0.15`, `money − 30%`.

**Стоимость проекта** (без обучающей проверки):

```
total = (BASE_COST + floors * COST_PER_FLOOR) * (1 - discount) * scenarioMult   // area = 1 lot
```

`BASE_COST = 30`, `COST_PER_FLOOR = 12`, максимальная скидка 0.3.

| Сценарий | Множитель стоимости | Одноразовая прибыль | Срок (тики 10 Гц) | Влияние на волю жителей |
|---|---|---|---|---|
| `repair` — ремонт | 0.4 | +40% от стоимости | 40 | небольшой плюс |
| `rebuild` — реконструкция | 1.0 | +90% | 90 | минус (выселение 30%) |
| `revitalize` — ревитализация | 1.5 | +130% | 120 | заметный плюс |
| `demolish` — снос и новостройка | 2.0 | +170% | 150 | сильный минус (выселение 100%) |

**Воля жителей (citizens' will)**. У каждого здания чанка есть воля `0..1`, базу которой задают тип, износ, культурная ценность и число жильцов; с каждым сценарием связан сдвиг (таблица выше). Диалог с жителями чанка может **сдвигать** базу: убеждение, страх, исторический аргумент, «тут вырос», поэтому один и тот же аргумент повторно не срабатывает (см. §10). Воля чанка — средневзвешенная по `residents`.

**Начисление**:
- старт реновации: списывается полная стоимость; здание `renovating`, идёт таймер стройки;
- конец стройки: здание `done`, `money += profit` (одноразовая), после — **рейтинг**: `rating += RATING_STEP * (will_chunk - 0.5) * 2`, т.е. при воле 1.0 — плюс, при 0.0 — минус (константа настраивается);
- отмена (`cancel`): здание → `idle`, прогресс и потраченные деньги не возвращаются.

**Запреты**: реновировать здания вне назначенного чанка; два проекта — в одном здании; сценарии дешевле, чем позволяет `money` (мгновенный `toast error`).

**Поражение** (`gameOver`): `rating < 0.25` или `money` меньше минимальной доступной стоимости любой реновации нуженой для прогресса — проигрыш (автоматический, обе причины вычисляет сервер). Игрок остаётся в комнате наблюдателем; его чанки передаются в общий пул.

## 9. Периодичность серверных циклов

| Частота | Содержимое |
|---|---|
| 10 Гц | движение игроков и NPC, таймеры стройки и раунда, рассылка `playerUpdate` |
| 4 Гц | `npcUpdate` |
| 1 Гц | сохранение в базу, распределение `stats` изменившимся игрокам |
| 2 с | очередь изменённых зданий → `chunkDelta` |
| 30 с | сохранение позиций/денег/прогресса игроков |

## 10. Память ИИ-жителей

Личность жителя общая на архетип (задаётся в коде сервера): состав чанка генерирует по архетипам местных (жители старого дома, коммунальщики, инвесторы и т.п.). Персональных профилей под игрока нет: хранится состояние на пару *(агент, игрок)*:

```
agent_state(agent_id, player_id,
 topics_mask,   -- битовая маска раскрытых тем (до 32)
 said_count,    -- всего реплик
 trust,         -- -100..100
 interest_json, -- вектор интересов (8 чисел)
 last_topic, last_ts)
```

Журнал `agent_memory` — лог событий, а не профиль. Повторная тема: агент переключает угол или прямо говорит «мы уже говорили» и меняет тему. `trust` от диалогов влияет на вклад агента в волю чанка.

**Очередь инференса**: все обращения к ИИ — через очередь с лимитом одновременных выводов (4 по умолчанию), FIFO; клиент видит «агент печатает». Подключение локальной LLM не меняет ограничение — она тоже через эту очередь.

## 11. Метрики и результат

- У игрока два показателя: `money` (штрафы/прибыль/доход) и `rating` (0..∞, старт 1.0).
- Score сессии = `money × rating`, пересчитывается на каждом изменении; в комнате — scoreboard по этому значению; лучший score игрока хранится в профиле (требование регламента).
- Поражение по §8 правило `gameOver`.

| `grants` | room_id + player_id + cx + cz (PK), cycles_held, deadline, status (`active`/`skipped`/`done`) |
| `npc_agents` | id, room_id, archetype, name, color, home_lot, will, route_json |
| `agent_state` | agent_id + player_id (PK), topics_mask, said_count, trust, interest_json, last_topic, last_ts |
| `agent_memory` | id, agent_id, player_id, topic, said_count, player_text, agent_text, ts |
| `chat_log` | id, room_id, chunk_x, chunk_z, player_id, agent_id, role, text, ts |
| `journal` | id, room_id, ts, kind, author, text, meta_json |

Обязательные индексы: `buildings(room_id, cx, cz)`, `agent_memory(agent_id, player_id)`, `chat_log(room_id, chunk_x, chunk_z)`, `grants(room_id, player_id)`.

## 13. Требования к реализации сервера

- Мир генерируется один раз детерминированно (по сиду, сид фиксируется на комнату) и сохраняется в базу; при старте сервер читает здания из базы.
- Изменения зданий пишутся в базу инкрементально и рассылаются подписчикам дельтами.
- Позиции, деньги, прогресс игроков сохраняются на дисконнект и раз в 30 секунд.
- Чат и журнал пишутся сразу при создании записи.
- Сервер — единственный авторитет по бюджету, рейтингу, штрафам, скору, результатам `chunkPick` и стоимости проектов.
